## Step 0 findings

### 0A Premise
- Real problem: building a machine-readable resume, and judging which jobs are realistic. Do-nothing: users stay on ChatGPT + Naukri + fake ATS scores.
- Builder attacks the pain directly. Faithfulness is invisible at signup; it must be sold as "every line is interview-defensible".
- Feed attacks a proxy: PRD §2 says "we do not compete on volume of job listings", but feed quality equals catalog volume, and catalog is blocked (TRD T-OQ-2). Paste-a-job (PRD §6.1) is the actual differentiator yet is framed as fallback.
- Scope premise: any profession, all stages, India + global, 1M users, free, in v1.

### 0B Reuse (no code exists)
RenderCV (Typst resume renderer), OpenResume (parser reference for parse-safety), JSON Resume schema (export interop), ESCO (planned), pdfminer.six/Poppler (planned).

### 0C Dream state
CURRENT: ChatGPT + Naukri + fake ATS scores → THIS PLAN: profile + builder + paste-match + tailor + catalog feed + alerts, all professions, 1M-user infra → 12-MONTH IDEAL: paste ANY job → honest verdict + defensible tailored resume in <2 min; feed earned by proven quality.

### Landscape (WebSearch; Aside unavailable)
- L1: India crowded with free ATS builders/checkers selling "ATS scores".
- L2: Keyword stuffing backfires; fabrication is the top failure; explainable matching exists mostly recruiter-side or in research.
- L3 (eureka): the moat is not the catalog; it is "is this job right for me + a truthful resume for it" on ANY job, from day 1.
